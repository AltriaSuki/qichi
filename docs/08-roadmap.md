# 08 · 开发路线图

> 一次只做一个任务。任务做完，把 `[ ]` 改成 `[x]` 并提交。
> 每个阶段结束时，两个人都在真手机上用几天，再决定下一阶段做不做、改不改。

## 怎么让 AI 做一个任务

每次新开一个 AI 会话，发这段话（改掉任务编号）：

```
读 CLAUDE.md，然后做 docs/08-roadmap.md 里的 P1-02。
先读相关文档和设计稿，告诉我你的实现计划：要改哪些文件、加哪些测试、有没有需要我决定的地方。
等我回复「可以」再动手。做完后跑测试，界面任务在模拟器里截图给我看。
```

AI 做完后，你检查三件事：测试是否全部通过、截图或演示是否符合设计稿、验收条目是否都满足。然后让它提交。

## 第 0 阶段 · 地基

- [x] **P0-01 共享模块** — 初始化 `shared/` 独立 Gradle 构建（Kotlin/JVM、kotlinx.serialization、JDK 21 工具链、Gradle Wrapper），`rootProject.name = "qichi-shared"`，`group = "app.qichi"`。实现 `UuidV7`、`CjkText.charCount()` / `readingMinutes()`、`Diff.lines()`（java-diff-utils），以及 `EntityType`、`MoodLabel`、`MoodReplyKind` 等枚举。
  - 验收：`cd shared && ./gradlew test` 通过；UUIDv7 按时间单调递增有测试；中文字数统计对中英混排、标点有测试。
- [x] **P0-02 服务端骨架** — 初始化 `server/`（Ktor + Netty，`application` 插件，Gradle Wrapper，`rootProject.name = "qichi-server"`，`includeBuild("../shared")`）。`AppConfig` 从环境变量读取（变量名与 `deploy/.env.example` 和 `deploy/docker-compose.yml` 一致）；未设置时使用 `deploy/docker-compose.dev.yml` 的本地默认值，但生产环境缺少 `JWT_SECRET` 等关键变量时拒绝启动；安装 JSON 序列化、problem+json 错误处理、请求日志（不打印正文）；启动时执行 Flyway 迁移（已有 `V1__init.sql`）；`GET /api/v1/health`。
  - 验收：`./gradlew test` 通过（Testcontainers 起 PostgreSQL，验证迁移成功和 health 返回）；按 `CLAUDE.md` 的命令本地运行成功；`docker build -f deploy/server.Dockerfile .` 在仓库根目录能构建成功。
- [x] **P0-03 Android 骨架** — 在 `android/` 创建工程（包名 `app.qichi`，minSdk 26，Compose + Material 3 + Hilt），`includeBuild("../shared")` 并依赖它；`BuildConfig.BASE_URL` 从 `local.properties` 的 `qichi.baseUrl` 读取；把 Noto Serif SC 与 Cormorant Garamond 字体文件（SIL OFL 许可，保留许可文件）放进 `res/font/`。
  - 验收：`./gradlew :app:assembleDebug` 通过；装到模拟器能打开，显示用思源宋体写的「栖迟」。
- [x] **P0-04 设计系统** — 按 `06-design-system.md` 实现四套天色、`skyAt()`、字号层级、间距常量，以及第 5 节组件清单中前 10 个组件（到 `CheckCircle` 为止）。做一个仅调试版可见的「组件陈列」页，四种天色可切换。
  - 验收：`skyAt()` 边界时间有单元测试；在模拟器截四张陈列页截图（四种天色）给人类确认。
- [x] **P0-05 导航骨架** — 单 Activity；底部四个标签各自独立返回栈；「一起」页三组标签；深链 `qichi://room/{roomId}/{page}[/{id}]`；各页面先放占位。
  - 验收：`adb shell am start -d "qichi://room/test/chat"` 能直接打开聊天标签；在「一起 → 心情」按返回回到「一起」，再按返回回到上一个标签。
- [ ] **P0-06 首次部署** — 按 `07-deploy.md` 在 VPS 上部署（AI 给出每条命令，人类确认后执行）。
  - 验收：手机浏览器打开 `https://你的域名/api/v1/health` 返回 ok；每日备份脚本已加入定时任务。

## 第 1 阶段 · 账号、房间、同步引擎

- [x] **P1-01 服务端鉴权** — 注册（第一个用户免邀请码，其余必须有效邀请码）、登录、刷新（轮换 + 重复使用检测）、登出、改密码；Argon2id；JWT 鉴权插件；登录接口限流。
  - 验收：集成测试覆盖：第二个用户无邀请码注册被拒（`registration_closed`）；旧刷新令牌第二次使用导致该设备所有令牌作废；错误密码 5 次后被限流。
- [x] **P1-02 服务端房间** — 建房间、查看、修改设置、生成邀请码（仅 owner、8 位去易混字符、7 天有效、满员 409）、接受邀请；统一的 `requireMember(roomId)`；`db/RoomWrite.kt`（分配 seq + 写 change_log + 提交后广播）。
  - 验收：非成员访问任何房间接口得到 404；并发 50 次写入后 `seq` 连续无重复（测试）；第三个人接受邀请得到 `room_full`。
- [x] **P1-03 服务端同步** — `bootstrap`、`sync`（区间内同一实体只返回最后状态、分页）、WebSocket `/ws`（`hello`、`changed`）。
  - 验收：集成测试：写入 3 次同一待办，`sync` 只返回 1 条且为最新；`limit` 分页的 `hasMore` 正确；另一个成员的 WebSocket 能收到 `changed`。
- [x] **P1-04 客户端网络与会话** — Ktor Client；令牌用 Android Keystore 加密保存；401 时自动刷新一次再重试；problem+json 解析为类型化错误；登出清除本地数据。
  - 验收：单元测试（Ktor MockEngine）覆盖自动刷新和刷新失败后跳回登录。
- [x] **P1-05 客户端同步引擎** — Room 数据库（V1 全部实体 + `sync_state` + `outbox` + `drafts`）；`SyncEngine.pull`；`OutboxWorker`（按房间先进先出、指数退避、4xx 与 409 处理）；前台 WebSocket；每 15 分钟的定期同步。严格按 `05-sync-offline.md`。
  - 验收：`05-sync-offline.md` 第 5 节列出的客户端测试全部实现并通过。
- [x] **P1-06 登录与建房界面** — 欢迎、注册、登录、建房间、输入邀请码加入、生成并分享邀请码。视觉遵循设计系统（设计稿里没有这几页，按规则设计后截图确认）。
  - 验收：两个模拟器：A 注册建房并生成邀请码，B 用邀请码注册后两边都能看到对方的名字。
- [ ] **P1-07 我的（基础）** — 资料（显示名）、成员与邀请、房间设置（房间名、纪念日、时区）、退出登录（`Me.dc.html`）。
  - 验收：A 改房间名，B 在 5 秒内看到变化（前台）。

## 第 2 阶段 · 今天、心情、待办、日程

- [ ] **P2-01 服务端心情** — 记录、删除（仅作者）、回应与收回回应。
  - 验收：非作者删除返回 403；回应同 id 重复提交只产生一条。
- [ ] **P2-02 服务端待办** — 新建、修改、完成（重复待办按 `nextId` 生成下一次，支持 RRULE 中的 DAILY / WEEKLY / MONTHLY + INTERVAL + BYDAY）、取消完成、删除；子任务。
  - 验收：每周日重复的待办完成后生成下周日的新实例，重复提交完成请求不会生成两个。
- [ ] **P2-03 服务端日程** — 新建、修改、删除。
  - 验收：常规集成测试。
- [ ] **P2-04 心情页** — 按 `Mood.dc.html`：情绪、强度刻度、备注、需要安慰、记下；对方最近心情与三种回应。
  - 验收：断网记录心情，联网后自动发出；对方能回应，回应不产生任何待办或提醒数字。
- [ ] **P2-05 待办** — 列表、新建、指派、截止日、子任务、重复、完成（`CheckCircle`）。
  - 验收：断网下完成和新建待办都能立即反映在界面，联网后同步到另一台设备。
- [ ] **P2-06 日程（列表版）** — 新建、编辑、按日列表；月视图放到 P4-07。
  - 验收：跨时区测试：房间时区 Asia/Shanghai、手机时区不同时，「今天」按房间时区计算。
- [ ] **P2-07 今天页** — 按 `Main.dc.html`：日期（房间时区）、主视觉（先用雾海插画）、最近心情、今日待办、今日安排、一年前的今天（本阶段只显示去年同日的心情）。没有数据的区块不显示，不放空状态说明。
  - 验收：四种天色下各截一张图给人类确认。
- [ ] **P2-08 显示设置** — 「我的 → 显示」：标准 / 大字、减少动画。
  - 验收：大字模式下今天页不截断、不重叠。

## 第 3 阶段 · 聊天、文件、回收站、推送

- [ ] **P3-01 服务端文件** — 上传（类型与大小校验、sha256、按房间分目录存放）、下载（鉴权、Range）、图片缩略图（200 / 400 / 800 宽，JPEG）。
  - 验收：非成员下载 404；超过大小 413。
- [ ] **P3-02 服务端消息** — 发送（文字、图片、文件；回复时由服务端从原消息截取前 60 字作为摘要）、历史分页、撤回（仅作者，清空正文）、删除进回收站、搜索（pg_trgm，排除撤回与删除）。
  - 验收：撤回后搜索不到原文，但仍能看到「谁在何时撤回」。
- [ ] **P3-03 服务端未读位置与回收站** — `read-marker`（只进不退）；回收站列表、恢复、彻底删除（消息、心情、待办、日程）。
  - 验收：旧值不会覆盖新值；恢复后实体与删除前完全一致。
- [ ] **P3-04 聊天列表与发送** — 按 `Chat.dc.html`：Paging 3、向上加载保持位置、「回到底部」、新消息提示、输入法不遮挡；文字消息走发件箱，待发送显示小时钟，失败可重试。
  - 验收：飞行模式下连发 3 条，恢复网络后按顺序各出现一次；1 万条消息滚动流畅。
- [ ] **P3-05 回复与跳转** — 长按回复；摘要可点，跳回原文并短暂高亮（需要时自动向上加载）。
  - 验收：跳转到 500 条之前的消息成功。
- [ ] **P3-06 图片与文件** — 选图、上传、发送、全屏看图、打开文件；离线时附件按钮置灰。
  - 验收：离线时无法选择附件，有明确但不啰嗦的提示。
- [ ] **P3-07 撤回、删除、回收站、搜索** — 「我的 → 回收站」页（设计稿没有，按规则设计）。
  - 验收：删除后从回收站恢复，消息回到原位置。
- [ ] **P3-08 未读** — 进入聊天推进未读位置；标签上显示未读数；「新消息」分隔线。不做已读回执。
  - 验收：在手机 A 读过，登录同一账号的手机 A' 的未读数同步清零。
- [ ] **P3-09 草稿** — 每个房间的聊天草稿存在本机，切走再回来、杀掉 App 都还在。
  - 验收：同上。
- [ ] **P3-10 推送** — 先问人类两台手机有无谷歌服务，再实现 FCM 或 UnifiedPush（服务端 `PushSender` + App 注册 + 通知点开走深链 + 免打扰时段）。推送里不含正文。
  - 验收：App 在后台时收到新消息通知，点开直达聊天。
- [ ] **P3-11 主视觉照片** — 房间设置里上传今天页主视觉照片；没有照片时继续显示雾海插画。
  - 验收：A 换照片，B 的今天页随之更新。

## 第 4 阶段 · 问答、计划、日历、灵感、AI

- [ ] **P4-01 AI 基础** — `jobs` 任务队列、`ai_jobs` 记录、`AiGateway`（openai-compatible 与 anthropic 两种实现）、提示词模板目录、每月额度、`/me/ai-usage`。
- [ ] **P4-02 问 AI（聊天）** — 点「问 AI」才调用；异步返回为一条 AI 消息；离线置灰；失败可重试。
- [ ] **P4-03 问答服务端** — 题库、每日一问（按房间时区）、答案在双方确认前互不可见、确认后同时揭晓；AI 根据共同历史出题，采纳后进题库。
- [ ] **P4-04 问答页** — 按 `Qna.dc.html`：今日一问、我的回答、对方未揭晓时显示蜡封信封、同时揭晓的动效、题库、AI 建议与采纳。
- [ ] **P4-05 计划** — 按 `Plan.dc.html`：负责人、阶段、里程碑、下一步、过程记录、完成记录；可无截止日期。
- [ ] **P4-06 待办挂到计划** — 待办可属于计划；计划页显示其待办。
- [ ] **P4-07 日历** — 按 `Calendar.dc.html`：日 / 周 / 月视图，显示日程、待办截止、计划目标、里程碑。
- [ ] **P4-08 ICS** — 导入、导出、只读订阅链接（可重置）。
- [ ] **P4-09 灵感** — 随手记；「一起」页底部的快速输入。
- [ ] **P4-10 一起页与今天页补全** — 按 `Together.dc.html` / `Together-Look.dc.html` 完成目录页；今天页加上「一问」「进行中」区块。

## 第 5 阶段 · 创作

- [ ] **P5-01 共同写作服务端** — 文稿、不可变版本、`baseVersion` 冲突 409、旧版另存为新版。
- [ ] **P5-02 共同写作客户端** — 按 `Writing.dc.html`：列表与编辑器互斥、返回条、Markdown 预览、标题大纲、中文字数与阅读时长、专注模式、本机字号行距、未保存内容存本机、重基线对比、历史版本逐行对比。
- [ ] **P5-03 留言板** — 主题、引用回复、修订标记、置顶、搜索、喜欢 / 拥抱 / 支持；可离线写、联网补发。

## 第 6 阶段 · 回看

- [ ] **P6-01 档案** — 偏好、共识、决定、边界、担忧、里程碑；可追到来源消息与历次修订。
- [ ] **P6-02 决定记录** — 问题、备选、各自关注点、最终决定、复查日期（到期提醒）。
- [ ] **P6-03 时间线** — 按年月回看决定、灵感、计划完成、双方都选中的照片。
- [ ] **P6-04 阅读** — 按 `Reading.dc.html`：书架、上传 EPUB、Readium 阅读器、各自进度、书签、摘录、标注、共同可见的感想、书内搜索、共读计划、离线缓存（上限与淘汰）。
- [ ] **P6-05 阅读里的 AI** — 选中段落请 AI 解释或对比。
- [ ] **P6-06 总结与年度回顾** — 周、月、自定义范围（带来源回链）；每年 1 月 1 日自动生成上一年的年度回顾，标注 AI 派生、不可撤回。
- [ ] **P6-07 一年前的今天（完整版）** — 加入照片、灵感、决定。

## 第 7 阶段 · 审稿与收尾

- [ ] **P7-01 审稿服务端** — 版本上传；文档转换（LibreOffice 无界面模式，建议单独一个 `converter` 容器，先与人类确认）；按页渲染图片与文字层坐标。
- [ ] **P7-02 审稿客户端** — 按 `Review.dc.html`：安全预览、按页 / 段落 / 单元格 / 幻灯片 / 图片区域批注与提议、讨论、接受、归档、版本差异。
- [ ] **P7-03 审稿 AI** — 每次单独授权；发现带原文证据与定位；跨版本追踪；可转为人工批注；不替人定稿。
- [ ] **P7-04 我的（完整）** — 按作者归总自己写下的内容、AI 使用记录、安全（登录设备、改密码）、通知设置。
- [ ] **P7-05 回收站与导出** — 回收站覆盖所有可删除类型；房间数据导出（不含撤回内容）。
- [ ] **P7-06 收尾** — 全面的大字与无障碍检查、长列表性能、一次完整的备份恢复演练。
